# クエストウォーク Instagram 投稿スキル

投稿文を一緒に作り、`instagram/posts/` に予約ファイルを置くところまでを担当する。
実際の投稿は GitHub Actions（`.github/workflows/instagram-publish.yml`）が予約時刻に自動で行う。
仕組みの詳細とセットアップは `instagram/README.md` を参照。

## 進め方

1. **内容を聞く** — 足りない情報だけ質問する（全部を一度に聞かない）。
   - 投稿の種類（下の「投稿の型」から）
   - 使う写真（パス、またはフォルダ）
   - 投稿日時（日本時間）
   - 大会の **日付・場所・距離・集合/ゴール時刻・参加費・定員・申込締切**
2. **事実は推測しない** — 日付・場所・料金・定員は、ユーザーがこの会話で言ったものだけを使う。
   下の「いつもの情報」や過去の投稿・サイトのソースから拾った情報は、その回も同じか「これで合っていますか？」と確認してから使う。
   （サイトの `app/faqs/page.tsx` は「保護者同伴が原則」、インスタでは「子供だけ預ける🆗」など、食い違いがある）
3. **お手本を読む** — `past-posts.md`（このスキルと同じフォルダ）から、同じ型の過去の投稿を読んでから書く。
4. **下書きを見せる** — 本文を1案（希望があれば2〜3案）チャットに出して、OKをもらう。
5. **ファイルを作る** — OKが出たら「ファイルの作り方」に沿って画像と予約ファイルを用意し、
   `node scripts/instagram-publish.mjs --check` を実行してエラーがないことを確かめる。
6. **公開の確認** — 「GitHub に push すると予約が確定します（写真もサイト上で公開されます）。push してよいですか？」と聞き、
   はっきりOKが出てから commit & push する。勝手に push しない。

## 口調・文体（@quest.walk の過去投稿から）

迷ったら `past-posts.md` の実例に合わせる。ここに書いたことより実例が優先。

**語り手** — 主催者本人が、自分の言葉で熱く語る。丁寧すぎない。企業SNSっぽい定型文（「〜をご紹介します♪」「ぜひチェックしてみてくださいね」）は使わない。
- 告知・案内は「です・ます」：「7:00集合です！」「雨天決行します！」
- 想い・考えは言い切りの常体：「ゲームでは感覚は養われない。」「人を育む1番の種だと思っている。」
- 子どもには熱いコーチ口調：「完歩できなかった子も、悔しい思いをバネにしてまた挑戦してくれ‼️」
- 参加者・大人には「みなさん！夏は早寝早起きしましょう！」のように呼びかける。

**見た目**
- 1行を短く（10〜20文字くらい）切って、こまめに改行。話の区切りには空行。
- 見出し・強調は【】：`【持ち物】` `【準備するもの】` `【NEWコース開拓】` `【パートナー企業様】`、本文中の強調も `【準備】` `【動】` `【体力】【精神力】【身体性】`。
- リストは「・」。補足は「※」。
- 区切り線（━━━）や 🗓📍 のような項目アイコンは使わない。日時・場所は素直に「8/15 土曜　開催 / グスクロード公園 / 7:00集合です！」と行を分けて書く。

**記号・絵文字・顔文字**
- 感嘆は ‼️ や ‼︎ を多用（「！」と混ぜる）。
- OK/NG は 🆗 ⭕️ ❌：「親子参加🆗」「草履🆗運動靴⭕️」「※傘は❌」
- 物や天気を絵文字に置き換える：🍙 🍌 🌀 ⤵️⤵️ 🤲。飾りのためだけの絵文字は付けない。
- 顔文字を1つくらい：`(°▽°)` `(ﾟ∀ﾟ)` `^ ^` 、お礼・お願いは `m(__)m`。

**大事にしている言葉・考え方**（自然に出てくるときだけ使う）
- 自分を超えろ／歩く、見つける、気づく／体力、メンタル、感性を歩いて磨く
- 歩く冒険、勇者たち、完歩、経験値、原体験、五感をフル活用
- 【準備】も冒険のうち：「この準備からクエストウォークは始まってます！」
- スマホ・AI時代に子どもから【動】【身体感覚】が奪われている → だからリアルな世界を歩く
- 南城市・津波古の自然、歴史、生き物、地域とのつながり

RPG用語（パーティ、ボス、レベルアップなど）を無理に足さない。過去の投稿で使っているのは「勇者」「冒険」「クエスト」「経験値」くらい。

## 投稿の型

| 型 | 中身（お手本は `past-posts.md`） |
|---|---|
| 開催告知 | 日付・曜日・集合場所・集合/スタート/ゴール時刻 → 一言 → 参加費 → 親子🆗/預ける🆗 → 【準備するもの】 → 申込方法 → 【パートナー企業様】 |
| 予告・NEWコース | 「どんな〜？」を重ねて期待をあおる短い投稿 |
| 持ち物 | 【必須持ち物】【持ち物】【格好】を「・」で。NGは❌ |
| 開催レポート | ルート（地名を1行ずつ）→ 距離・時間・気温 → 完歩の報告 → 学び・工夫（例【熱中症対策】）→ パートナー企業へのお礼 |
| 想い・考え方 | 社会の問題提起 → なぜ歩くのか → クエストウォークの狙い。常体で言い切る |
| パートナー企業紹介 | 「パートナー企業紹介①」→ 会社の紹介 → ✅で特徴 → クエストウォークとのつながり → お礼 → ▼詳細はこちら |
| 地域イベント | 【タイトル】→ 日時 → 理由（ゆるく顔文字）→ ※で持ち物 |

## 本文のルール

- **ハッシュタグは基本なし**。付けるのは地域イベントや企業紹介のときに3〜5個（`#クエストウォーク #南城市イベント #毎月2回開催` など）。ユーザーが増やしたいと言ったときだけ増やす。
- 告知・レポートの最後は【パートナー企業様】と@アカウントを1行ずつ並べ、「いつもサポートありがとうございますm(__)m」で締める。
- 申込の誘導：「ご質問、参加希望者はDM下さい！ / プロフィール欄に申込フォームあります🤲」
  - 本文中のURLはクリックできない（企業紹介の ▼詳細はこちら は慣例として書いてよい）。
- 長さは型に合わせる。予告や持ち物は数行、告知は20〜35行、想いは15〜30行。2200文字・ハッシュタグ30個が上限（`--check` で検査）。

## 写真の注意

- **子どもの顔がはっきり写っている写真**は、保護者の掲載許可が取れているかを一度ユーザーに確認する。
- ゼッケン・名札・車のナンバーなど個人が分かるものが写っていないか見る（画像を Read で確認）。

## ファイルの作り方

1. 投稿ごとに名前を決める：`YYYY-MM-DD-内容`（例 `2026-11-05-autumn-quest`、英数字とハイフンのみ）
2. 画像を `public/instagram/<名前>/1.jpg, 2.jpg …` に置く。JPEG 以外（HEIC・PNG）は macOS の `sips` で変換する：
   ```bash
   sips -s format jpeg -s formatOptions 85 -Z 1440 元の画像.HEIC --out public/instagram/<名前>/1.jpg
   ```
   - `sips -g pixelWidth -g pixelHeight` で縦横を確認。**縦長は 4:5（例 1080×1350）まで、横長は 1.91:1 まで**。
     それより縦長な写真（スマホの 9:16 など）は Instagram に拒否されるので、`sips -c <高さ> <幅>` で 4:5 に切り抜く（どこを残すか迷う場合はユーザーに確認）。
   - 1枚 8MB 以下。
   **リール（動画）の場合**：動画は `instagram/videos/<名前>.mp4` に置く（サイトには公開されない）。
   - MP4 か MOV、縦 9:16（1080×1920）推奨、3秒〜15分、300MB 以下。
   - 長さとサイズは `mdls -name kMDItemDurationSeconds -name kMDItemPixelWidth -name kMDItemPixelHeight 動画.mp4` と `ls -lh` で確認。
   - 大きすぎる場合は Mac 標準の `avconvert` で圧縮する：
     ```bash
     avconvert --source 元の動画.MOV --preset Preset1920x1080 --output instagram/videos/<名前>.mp4
     ```
   - 表紙を選びたいときは JPEG を `public/instagram/<名前>/cover.jpg` に置き、予約ファイルに `cover:` を書く（省略すると Instagram が自動で選ぶ）。
   - GitHub は1ファイル100MBまでなので、それを超える動画は圧縮してから置く。
3. `instagram/posts/<名前>.md` を `instagram/posts/_template.md` の形で作る：
   ```
   ---
   publish_at: 2026-11-05 19:00
   images:
     - 2026-11-05-autumn-quest/1.jpg
     - 2026-11-05-autumn-quest/2.jpg
   status: scheduled
   ---
   本文…
   ```
   リールなら `images:` の代わりに `video: <名前>.mp4`（必要なら `cover: <名前>/cover.jpg`）を書く。
   - 日時は日本時間。投稿は予約時刻から30分以内（GitHub の混み具合で多少遅れる）。
   - ユーザーがまだ迷っているときは `status: draft` にしておく（draft は投稿されない）。
4. `node scripts/instagram-publish.mjs --check` でチェック。

## 予約の確認・変更

- 「予約一覧を見せて」→ `node scripts/instagram-publish.mjs --check` の結果と、各ファイルの1行目を表で見せる。
- 日時や本文の変更 → ファイルを書き換えて push すればよい（`status: scheduled` のまま）。
- 取り消し → `status: draft` にするかファイルを削除して push。
- `status: error` のファイル → `error:` の内容を読んで原因を説明し、直したら `scheduled` に戻す。
- 投稿済み（`published`）のファイルは記録なので消さない。投稿済みの内容を直したい場合は Instagram アプリで編集してもらう。
